## Top picks

### merge-now

- **#1517 - ReDoS in user-query frontmatter strip.** The regex at `MemoryProxy/src/common/user-query-extractor.ts:182` has nested ambiguous quantifiers (`\s*` can eat the newline). I checked it in node: "---\n" plus 32/36/40 `foo:` lines took 0.3 s / 0.8 s / 5.3 s, and each added line about doubles it. `extractUserQueryText` runs synchronously on the request path (`tdai-l1-recall-injector.ts:54`, `tdai/recorder.ts:26`, the agent adapters), so one pasted YAML-like message can stall the whole proxy. The fix is a linear line scan with tests. Merge it first (see Duplicates for the merge order).
- **#1080 - bridge L1 session lookup misses Codex.** `loadSessionIdsL1` in `memory/memory-bridge.ts:153` and `skill/skill-bridge.ts:303` only tries the bare key, `codebuddy:` and `claude-code:`. Codex sessions are stored as `codex:<id>`, so a Codex agent's memory/skill curl calls fall to the L2 binding lookup and get 401 when that misses. The Codex init stores state under `codex:<sessionKey>` (`session/codebuddy/init.ts:553`), and the injected curl sends the bare session id (`tdai/identity.ts:31`). This is a 2-line list extension in both files with no risk. #1005 (Hermes) edits the same lines; skip it.
- **#1349 - Bearer on proxy auth/verify.** MemoryCore checks `server.apiKey` on `/v3/meta/*`, including `/v3/meta/auth/verify` (`MemoryCore/src/gateway/server.ts:1029`, `1311`; the earlier internal block only covers `/v3/internal/meta`), and our `compose.yaml` already passes `TDAI_GATEWAY_API_KEY: ${MEMORY_CORE_GATEWAY_API_KEY}` to core. But `MemoryProxy/src/auth.ts:76-84` sends no Authorization header. When that key is non-empty, every proxied model request fails auth (401). It does nothing while the key is empty, so it is safe to take now and it unblocks hardening MemoryCore. To use it, set `auth.apiKey` in compose. Prefer it over #1211.

### consider

- **#1579 - Claude Code session-init does not persist a bypass on a metadata timeout.** We run `headerAutoSelect`. Today a transient MemoryCore metadata error writes `bypassed: true`, so the whole Claude Code session runs with no memory injection and no L0 writes. After this PR the request passes through and the next request retries. It also fetches only the header team's directory, which saves N team calls. It is a session/ change (needs-owner-read). It conflicts with #1429 only on the EOF line.
- **#1429 - session-init with zero tasks.** Teams with no task currently bypass memory entirely (Claude Code and the codebuddy/codex init path). The PR registers with team+agent and no task, so it reverses upstream's "team+agent+task or nothing" contract. Decide as a product choice. The alternative already in use upstream is `sessionInit.defaultTaskId`, which our compose does not set.
- **#1279 - Codex injection into `instructions`.** This is a real gap: `injectCodexAssets` (`pipeline/runners/codex.ts:244`) silently injects nothing unless `input[0]` is a message with array content. But dynamic text in `instructions` costs the prompt cache, and the ChatGPT-subscription Codex backend (our pool is Codex-only) may reject modified instructions. Test it live through the pool before you merge.
- **#1519 + #1521 - cleaner L0/L1 text for Claude Code.** #1519 strips more Claude Code harness blocks (task-notification, local-command-*, bash-*, the compact "This session is being continued" summary). #1521 keeps instructions the user typed while a tool ran, which Claude Code puts inside `<system-reminder>`. They complement each other, but both rewrite `extractUserQueryText`: apply #1521's unwrap before #1519's block strip, then rebase both onto #1517. #1519 also edits `tdai-l1-recall-injector.ts`, and its tests were dropped from the branch.
- **#1722 - system cache_control dropped.** `serializeSystemMessage` (`injection/adapters/anthropic.ts:198`) collapses a single text block to a plain string. That drops `cache_control`, plus any sibling non-text block, so a prompt-cache breakpoint is lost. The fix is small and has tests, but it is in the adapter our fork changed (8a350b6, 4cfb845). Have the owner read it with the see-overlap results.
- **#1361 - skill download recipe.** The injected `skill_files_read` text tells agents that `curl -o` on files/read returns raw bytes. It returns a JSON envelope, so scripts saved that way are broken; only files/download returns bytes. The PR also fixes zero-byte files. Low risk, but it changes injected prompt text, and existing sessions keep cached blocks (see #1431).
- **#673 (partial) - unauthenticated rate-limit admin.** `GET/PUT/DELETE /v3/admin/rate-limits` (`server.ts:159-161`) has no auth today. Cherry-pick only the `routes/rate-limits.ts` hunk. Do not take the `admin-auth.ts` fail-closed change: it disables all admin endpoints when `admin.apiKey` is empty. Do not take the git-fetcher regex: `/\s|-c|--/` rejects normal URLs such as `.../my-cool-repo`.
- **#1346 - mem: command recognition under Claude Code 2.x.** Take it only if we use `mem:` commands. It fixes missed `mem:session-reset` and replay of old commands after a tool_result turn.
