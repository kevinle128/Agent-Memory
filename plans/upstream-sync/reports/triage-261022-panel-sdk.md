## Top picks

### merge-now
- **#1588 page fixed assets before template allocate.** `allocateKnowledgeToAgent` (MemoryPanel/src/panel/http/routes/meta/proxy.ts:408) reads `agent-fixed-asset/list` with no paging (default 20 rows), then calls `agent-fixed-asset/set`, which replaces the full binding set. An agent with more than 20 bindings loses every binding past 20 when template knowledge is allocated. That is silent data loss. The fix reuses the `fetchAllMetaListItems` helper that already exists at knowledge/common.ts:269, with the same pattern that allocate-routes.ts:95-118 already uses. On a list error it now throws, and the caller at proxy.ts:330 catches and logs the error. Verified: HEAD uses `extractListItems` only at proxy.ts:418 (the line that the PR replaces), and `MetaEnvelope` is exported from kernel/envelope.ts:3, so the swapped import compiles. Risk is low.
- **#1637 page KS-only list items.** `fetchKsOnlyItems` calls `kc.wikiList` / `kc.codeGraphList` with no paging, so the Hub never shows the 21st and later KS-only code graphs or wikis. The port already accepts `limit/offset` (knowledge-client-port.ts:268,296). The loop has a limit of 10 pages x 100 and stops on `total` or on a short page. There is a test. Risk is low.
- **#1713 L2 row more-actions menu.** Premise checked: the global `[role='button']:not(:disabled):active { transform: scale(0.97) }` at MemoryPanel/web/src/index.css:93 makes the whole L2 row shrink when you press, so the "more actions" button moves out from under the pointer. The PR's selector (0,3,1) has higher specificity than the global rule (0,3,0). The keyboard guard `e.target !== e.currentTarget` is correct. The change is 14 lines and frontend only.

### consider
- **#1230 accurate agent memory layer counts.** This is a real bug for us. Panel L0/L1 views send `user_id = asset.owner_user_id`, but Claude Code/Codex traffic through MemoryProxy writes with each client's own user id, so the Panel undercounts or shows empty layers. The fix also changes the MemoryCore gateway: when the request body has no `user_id`, v2 `conversation/query|count` and `atomic/query|count` no longer filter by the resolved default user bucket. This widens reads for any v2 caller in the same team+agent, so it is needs-owner-read for tenancy. It also moves the Panel from /v3 to /v2 for L0/L1, removes trailing newlines in several files, and rewrites `parseChatMemoryAssetId`, which overlaps with 909.
- **#1453 agent delete without SkillCore.** This fix is correct and conservative: it accepts only an exact `404 + "Skill module not enabled"` on the first page. It matters only if our MemoryCore runs with no skill module. Check our compose/env before taking it. If SkillCore is enabled, drop this PR to "wait".
- **#1624 large test PR with embedded fixes.** Do not merge it whole (57 files, +3.7k lines, new package scripts, docs). Cherry-pick these source fixes: SerialQueue no longer deadlocks when a task throws synchronously (MemoryKnowledge, which we run); local extract lock cannot be renewed after it expires; `IngestProgressStore.clear` no longer erases a newer run; profile-sync now recurses into nested L2 `scene_blocks` (without this, sync-back can delete nested files). The `metadata-service.ts` change loads explicit ACLs for restricted assets for active non-admin members, which widens access. An owner must read it. Do not take the MemoryProxy `src/session/__tests__/*` files or the vitest/package.json changes without first running them against our session code. Our fork changed session behavior in 043d3a1, so those tests can assert upstream behavior that we changed on purpose (needs-owner-read).
